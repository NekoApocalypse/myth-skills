# Convict Conditioning — New Blood Reference

## Weekly schedule

| Day | Training | Volume |
|---|---|---|
| Monday | Pushups + Leg Raises | 2–3 work sets per chain |
| Tuesday | Rest | — |
| Wednesday | Rest | — |
| Thursday | Rest | — |
| Friday | Pullups + Squats | 2–3 work sets per chain |
| Saturday | Rest | — |
| Sunday | Rest | — |

New Blood uses only the four basic chains. Bridges and handstand pushups are held back until later.

## Progression rules

1. Train the chain at its current step.
2. Use 2–3 work sets. If the progression target requires 3 sets, perform 3 work sets when testing readiness to advance.
3. Record the actual repetitions completed in every work set.
4. Count only controlled repetitions performed with the intended range of motion and acceptable form.
5. Do not count repetitions completed through obvious form breakdown. Pain is a stop signal, not a progression signal.
6. A chain is **ready to progress** when all required work sets reach the progression target in the same session with clean form.
7. On the next scheduled session for that chain, move to the next step. Start conservatively at the new step rather than immediately chasing its progression target.
8. If the new step cannot be performed with controlled form, return to the prior step and continue building capacity.
9. Judge each chain independently. One chain can remain at Step 2 while another reaches Step 6.
10. The original New Blood template is normally retained until the trainee has moved past roughly Step 6 in all four chains; only then is the next program necessary.

## Agent evaluation rule

After each logged workout:

- Read the current step from `02_current_status.md`.
- Compare the logged work sets with the progression target above.
- If every required set meets or exceeds the target with clean form, mark the chain `ready_to_progress: yes`.
- Otherwise mark it `ready_to_progress: no`.
- Do not change the current step merely because the user says the exercise felt easy.
- When a progression actually occurs, update `02_current_status.md` and add a dated entry to its progression history.
